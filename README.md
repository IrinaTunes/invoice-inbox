# invoice-inbox

Сканы и PDF счетов → один XLSX-реестр с проверкой ИНН по контрольной сумме и сверкой итогов. Всё, что не удалось распознать или что не сходится, попадает в отдельный лист «Проблемы» — программа не выдумывает значения и не глотает ошибки молча.

![CI](https://github.com/IrinaTunes/invoice-inbox/actions/workflows/ci.yml/badge.svg)

## Зачем

Бухгалтерия и фрилансеры получают счета пачками: часть приходит в PDF, часть — фотографиями. Переносить реквизиты в таблицу руками — 2–3 минуты на документ и стабильные опечатки в ИНН и суммах. Утилита делает это за секунды и сама помечает документы, которые нужно посмотреть глазами.

## Что делает

1. **Извлечение текста.** Для PDF сначала пробуется текстовый слой (`pdftotext -layout`), и только если его нет — рендер в 300 dpi и `tesseract -l rus+eng`. Картинки идут сразу в OCR.
2. **Разбор реквизитов.** Тип документа, номер, дата (числовая и «03 ноября 2026»), поставщик, покупатель, ИНН, КПП, суммы без НДС / НДС / итого.
3. **Проверки** (каждая находка — отдельное замечание):
   - ИНН 10 или 12 цифр **по контрольной сумме** (алгоритм ФНС), а не просто «похоже на ИНН»;
   - формат КПП;
   - `без НДС + НДС = итого`;
   - дата не в будущем и не старше допустимого срока;
   - средняя уверенность OCR ниже 75% → «проверить вручную».
4. **Выгрузка.** XLSX: лист «Реестр» (фильтры, закреплённая шапка, денежный формат, подсветка проблемных строк), «Сводка», «Проблемы». Дополнительно JSON.

## Установка

```bash
brew install poppler tesseract tesseract-lang   # macOS: pdftotext, pdftoppm, OCR
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

Linux: `sudo apt install poppler-utils tesseract-ocr tesseract-ocr-rus`.

## Запуск

```bash
python -m invoice_inbox samples -o out/registry.xlsx --json out/registry.json
```

## Что получается на выходе

Фрагмент листа «Реестр» из демо-прогона:

| Файл | Тип | Номер | Дата | Поставщик | ИНН | Итого | Статус |
|---|---|---|---|---|---|---|---|
| invoice-142.pdf | Счёт на оплату | 142 | 12.11.2026 | ООО «Ромашка» | 7701234560 | 48 000 | ок |
| invoice-88.pdf | Счёт-фактура | 88 | 03.11.2026 | ИП Соколов Дмитрий | 7709876545 | 14 400 | ок |
| scan-503.png | Счёт на оплату | 503 | 20.11.2026 | ООО «Камертон-Сервис» | 7707083894 | 6 200 | проверить |

Третья строка — демонстрация: скан распознан через OCR, ИНН намеренно битый, итог не сходится с НДС. Оба факта попали в реестр и в лист «Проблемы».

## Тесты

32 теста: контрольные суммы ИНН/КПП (в том числе реальные ИНН), ловушка «Сумма без НДС» в строке со словом НДС, ставка 20% вместо суммы, разбор даты словом, генерация XLSX с чтением обратно, сквозной прогон на `samples/` с OCR.

```bash
pytest -q          # 32 passed
ruff check .       # All checks passed
```

## Ограничения (честно)

- Табличные счета с позициями по строкам **не разносятся по строкам** — извлекаются только итоги.
- Рукописный текст, печати и подписи поверх цифр OCR не читает.
- Сканы ниже 200 dpi и с сильным наклоном требуют предварительной подготовки.
- Реквизиты стоит выборочно сверять глазами: программа помечает проблемные документы, но не заменяет проверку человеком.
- Поддерживается только российская атрибутика (ИНН/КПП/НДС).

## Структура

```
invoice_inbox/
  extract.py    текст из PDF/скана + уверенность OCR
  parse.py      регулярные выражения → поля счёта
  validate.py   ИНН/КПП/суммы/даты, модель Invoice
  export.py     XLSX (3 листа) и JSON
  cli.py        CLI и печать отчёта
samples/        демо-документы (PDF с текстовым слоем + «скан» PNG)
scripts/        генерация демо-документов
tests/          32 теста
```
